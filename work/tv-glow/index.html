TV Glow

Real-time ambient lighting for Android TV

Role
Personal project
Year
2026
Code
github.com/j4dgpt/tvglow

Overview

No cloud and no sync box. The app captures the screen at 96 by 54 pixels, samples colour zones around the edge, smooths them, and streams per-zone colour to the strip over UDP.

It speaks Govee's undocumented LAN realtime protocol and WLED's realtime protocol, and ships a phone remote served from the TV itself. CI builds the APK on every push.

What I built

  • Screen capture at 96 by 54 with letterbox detection, so black bars never drive the lights.
  • Colour correction through a calibrated RGB cube with trilinear blending, so the strip matches the TV.
  • A greedy command scheduler that sends the updates removing the most visible error first (OKLab distance).
  • A UDP liveness monitor and network rescan, because UDP never reports that a strip stopped listening.
  • A phone remote (HTML served by a tiny web server on the TV) and an APK built by GitHub Actions.

Architecture

Hard parts

UDP never tells you it failed

A strip that changed address or had LAN control switched off looks exactly like one that works. StripMonitor listens on the reply port, probes status and rescans the network to find a strip that moved.

Latency from a command queue

Updating segments one by one builds a queue on the strip, which reads as lag. The scheduler paints groups of segments per command, chosen by perceptual error.

Known limits

  • DRM-protected apps such as Netflix capture as black, so the strip goes dark.
  • HDMI inputs usually cannot be captured on Android TV.
  • The Govee realtime protocol is undocumented and a firmware update could change it.
