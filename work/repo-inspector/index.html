AI Repo Inspector

A code review tool for humans and AI agents

Year

Private repository

Overview

The tool lists the files changed against a base ref, optionally runs validation commands, and renders the result as Markdown or JSON. The CLI sets its exit code from the outcome; the MCP server exposes the same review to an AI agent.

The assessment was to investigate and improve an existing implementation. I fixed four issues, worst first, and documented how each was reproduced.

What I built

  • Closed an arbitrary file write: a crafted git ref was being passed to git diff as an option.
  • Fixed an MCP tool that reviewed the wrong repository on every call without raising an error.
  • Made one failing check report as failed instead of discarding the whole review, and made command execution over MCP opt-in.
  • Added a Vitest suite that spawns the real MCP server and speaks JSON-RPC over stdio, plus CI for typecheck, build and tests.

Architecture

Hard parts

Arbitrary file write through a crafted ref

The base ref was interpolated into one argv token, so a ref of --output=/tmp/x reached git diff as its own option and wrote the diff to that path. It was reachable over MCP, where the ref comes from an agent.

An MCP tool that was wrong on every call

The schema declared repo_path while the handler read repoPath. The path was always undefined, so every call silently reviewed the server's own directory and never raised an error. The fix ships with a test that spawns the real server, because the bug is invisible to any test that imports the handler directly.

Stack

  • TypeScript
  • Node.js
  • Model Context Protocol
  • Vitest
  • GitHub Actions

Known limits

  • Change detection is file-level, with no hunk parsing.
  • No severity model; findings are reported flat.
